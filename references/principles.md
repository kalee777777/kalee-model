# A working 30-principle constitution (sanitized)

> Drafting scaffold for your own constitution — this is a real one, field-run on a B2B industrial-export desk, with every case anchor rewritten so no client, company, or person is identifiable. **Do not adopt these as yours**: your principles must be anchored to *your* logged decisions or the validator (and the point) fails. Group titles are one way to slice it — find your own.

## I. Execution logic (P01–P08)

| # | Principle | Anchoring scenario (sanitized) |
|---|---|---|
| P01 | **Leverage first question** — anything recurring gets "can this never need a human again?" before "how do I do it?" | support-inbox polling replaced by a 15-min auto-router; replies surface as task cards |
| P02 | **Framework before content** — when dimensions multiply, build the positioning frame first; before any build, a plan (architecture / contracts / red lines / decisions reserved for you) | outreach stopped drifting once every letter had to state its 4-axis coordinates first |
| P03 | **Dry-run before automation** — every new pipeline gets one full manual pass on real data before it's frozen into code | new signal pipeline hand-run once: 83 events → 10 candidates → 2 actions, five rule fixes surfaced on day one |
| P04 | **Evidence tiers, not vibes** — every claim carries 实据/推断/TBC (evidence/inference/TBC); no evidence → give a range, never invent | market-sizing chapters rejected twice until company-name lists + outreach paths were mandatory |
| P05 | **Incidents ship rules** — the deliverable of an outage is a reusable rule (checklist / fallback / runbook), not "fixed" | a keyfile-eviction outage produced a 3-tier fallback + runbook; the class of failure, not the instance, was killed |
| P06 | **Humans at judgment points only** — approvals, grading finals, outbound sign-off, negotiations are yours; execution is the system's; a judgment point can't be rushed past you verbally | a batch-approval shortcut was rolled back and banned — approvals belong to a named human action |
| P07 | **Dual-channel everything critical** — smart-but-flaky primary + dumb-but-deterministic fallback + de-dup gates | the smart automation missed a run; the dumb cron fired anyway |
| P08 | **Funnel with gates, never all-at-once** — market scan → country deep-dive → customer map → named accounts → tiered outreach; hard gates + vetoes at each layer | B2B entry shipped as map → named list → tiered touch, one layer of evidence at a time |

## II. Reading people (P09–P14)

| # | Principle | Anchoring scenario |
|---|---|---|
| P09 | **Adversarial lens before words** — who is across the table, what do they want, what do they fear, who else is bidding; stacked red flags = one veto | fake-buyer scam (urgent off-platform + zero-spec "order" + odd meeting link) killed before money moved |
| P10 | **Read the motive switch** — what actually drives this person (their KPI this quarter), design straight at it | a new VP reorganizing the supplier base = the entry window; the pitch addressed *his* task |
| P11 | **Read well, externalize the empathy** — decisive, low-empathy negotiators keep the reading skill and ship empathy as **process**: forced empathy pass on drafts, ≤3 personal notes per contact, LTV-before-concession | the compensation checklist lives in the review step, not in the mood |
| P12 | **Cadence over pressure** — grade-based rhythm (A +7 / B +14 / C +30 / D +45 days); waiting periods feed value, not reminders; one bump max, then silence cycle | slow-decider thread left alone for a quarter — reopened with news, not a nudge |
| P13 | **Zero aggression outbound** — winning the argument loses the account; today only a facts-impact-expectation letter, solutions tomorrow; the angry draft never ships | the 24h rule caught every escalation draft before it could leave |
| P14 | **Optimism finds, checklists defend** — intuition proposes, the risk checklist disposes; never skip the checklist on a trigger condition | trigger-condition checklist outranked an exciting-looking deal |

## III. Assets & leverage (P15–P16)

| # | Principle | Anchoring scenario |
|---|---|---|
| P15 | **Compounding assets** — before doing a thing, ask what artifact outlives it (playbook / course / open-source / checklist) | an internal tool stripped of brands and open-sourced became an inbound funnel |
| P16 | **Parallel agents, one truth** — many agents/sessions may work at once; one source of truth; derived files never write back; outbound always exits through a single human | two parallel research sessions merged cleanly; only the truth file was edited |

## IV. Deal judgment (P17–P24)

| # | Principle | Anchoring scenario |
|---|---|---|
| P17 | **Two-source confirmation** — one source gets you to "candidate"; a second independent source (news / customs / expansion evidence) upgrades to committed | a hiring signal became an A only after an independent investment-news hit |
| P18 | **Downgrade with a window** — weak-fit leads drop to low cadence, but the scenario note stays; downgrade ≠ blocklist | a defense-perimeter scenario kept on file while the lead cooled |
| P19 | **Drop the masks** — agency/consultant fronts are excluded immediately; chasing them burns sequence budget | recruiter-posted "signals" recognized and excluded in one pass |
| P20 | **Recipient discipline** — verified inboxes only; inferred ones labeled "verify before send", failed verification = dropped; multi-inbox so a bounce costs nothing; target the best-fit *functional layer*, not the highest title | a bounce-killed address swapped for a verified one; the better contact was one layer down, not up |
| P21 | **Verify before promising** — spec/cert/stock claims verified with the factory before any letter carries them; trade-remedy-affected pricing lives in clauses, not prose | a quote held two days for factory confirmation — document risk beats speed |
| P22 | **Trust via plain facts** — delete the meta-talk ("not a pitch…"); a verifiable deliverable list carries the trust | a rewrite that removed every self-referential line outperformed the clever version |
| P23 | **Offer fits the function** — one letter solves one person's current task; dual-function reader → two parallel deliverables | cost benchmark for the supply side + qualification pack for the quality side, same email |
| P24 | **Timing windows** — send windows from open-rate history × timezone; seasonal buying cycles beat copy | a catalog-season letter timed to the buyer's annual assortment window |

## V. Outreach & closing (P25–P30)

| # | Principle | Anchoring scenario |
|---|---|---|
| P25 | **First touch = endorsement** — open with on-point evidence (their brand, a same-industry project), never a generic product intro | a same-class project reference in the subject line of a cold email |
| P26 | **Use the intel, never expose the source** — customs data / monitoring / research used for internal targeting only; never cited to the prospect | a spec match was referenced obliquely; the data source was never named |
| P27 | **Every follow-up carries a deliverable** — a ready spec matrix, a prefilled form ("just correct my assumptions"), a one-word-reply path; check-ins are taking, deliverables are giving | a 45-day-silent thread woke to "reply US or EU and the matrix lands today" |
| P28 | **Screen the false signals** — auto-replies and ticket receipts ≠ human replies; cross-check opens + content before acting on a "reply" | an auto-reply flagged "answered" was unmasked by open-data; the thread restarted correctly |
| P29 | **Conditional sends** — escalation drafts carry fire-gates (only if predecessor got no reply AND no bounce; a reply voids it); the executive line never fires while the working-level line is alive; IM channels respect cultural windows | the CEO-line draft sat gated until its trigger actually cleared |
| P30 | **Endings keep the door open** — breakup-style close: no blame, explain the silence as a professional choice, one-line reopen condition, well-wishes; nurture, never blocklist; a dead project ≠ a dead account | a no-reply thread closed gracefully and reopened months later through a different product angle |

*Structure notes: groups are presentation; the validator only cares that each principle cites ≥1 real case, and that any principle touching a personal weakness carries a `compensation` field.
